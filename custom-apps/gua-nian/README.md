让角色过上自己的一天，并在TA的一天里「想起你」。灵感来自 AstrBot 的私人陪伴类插件，但按 Float 的能力重新设计，不是移植。

## 0.9.32：话头更新沿用原条目

同一件话头/日子的 keep.id 现在用于定位更新，保留原 ID、记下时间及关联记录，不再因换措辞新建。没有 ID 时，按同类条目的规范化文字判重；未知 ID、类型不符或匹配多条时不擅自新建/合并。已有条目重复提及也会持久化刷新时间。

## 0.9.27：旧历史核对、跨页面收取与时区（本地候选包）

旧消息按所有云端输出共同核对，避免两条同文回复争用同一组镜像。完整且唯一对应的气泡合并；无法唯一对应、或明显延迟收取时刻附近的无编号旧角色记录，单独列为待核对资料，不计作新发言、新承诺或额外未回应轮次。原始数据库记录保留，不能凭缺失的编号还原真实发生次数。

宿主回传箱使用浏览器共享互斥锁，锁覆盖解析、落盘和确认；取得锁后先从 IndexedDB 补齐另一个页面已保存的消息，再判重复。已有持久批次只补确认，不再走回复插件。提交后通知其他页面刷新聊天缓存，页面关闭时锁由浏览器释放。该保护适用于同源、共享数据库且支持 Web Locks 的页面；不支持安全互斥的浏览器保留云端消息并暂停收取，不退回不安全的并发路径。

计划现在独立携带 tzOffsetMin。复核与成文依次使用有效的日程、生成原料、独立偏移、旧 IANA 时区或冻结请求信息；null、空值和非法值不冒充 UTC，明确的 0 仍有效。无法恢复时暂停并提示重新同步，约定不按猜测时间预约。临时起念不再从旧时刻反推时区。

更新需发布宿主、更新三个个人云函数、导入 0.9.27 ZIP 并同步计划。沿用 schema 12，本轮不新增 SQL。公开包 `/custom-apps/gua-nian-0.9.27.zip` 需宿主发布后才能在线下载。A6 设备接管、B18 异常起床时间按要求未处理；未做个人云或手机实测。

## 0.9.23：约定任务与云端连续上下文

“约定”复用原惦记账本类别，区分你的事、角色承诺和双方约定。角色明确说“三点半回家一趟”也会提取；有日期时间的约定直接挂任务，不再交给普通起念随机抽取。改期更新同一编号和版本，完成、取消撤销旧任务；发送进展只标记提过，不冒充事情已完成。手动记一件也可以选择归属。

判断和生成共用按会话合并的聊天镜像与云端回传箱，包括手机尚未收取的回复；镜像批次带编号时去重。读取失败暂停并重试。同会话生成使用数据库租约，成文前后核对约定版本，普通主动消息的间隔按实际生成时间计算。普通消息仍遵守原概率和降速；明确约定免随机概率作罢，保留主动发送的忙碌顺延和睡眠等待。

已记下的约定按任务扫描执行；新约定通常在下一次云端复核扫描（每 5 分钟）识别，明显约定不再等待普通 25 分钟判断间隔，仍遵守模型调用总上限。未来 31 天内的约定可提前寄存，更远的先留账本。云端任务不等于手机已展示或用户已读；通知仍取决于系统推送环境。旧版已按收取时间入库的历史消息不会自动重写。

## 0.9.21：忙碌回复迁到聊天插件

先更新宿主，在「设置 → 聊天插件 → 官方插件」安装并启用「忙碌回复」，再更新挂念。插件首次读取时导入原有被动回复设置（包括关闭、0 分钟和 0%）；之后等待间隔、偷空概率、睡眠回复和紧急优先只在插件设置中修改。挂念保留原字段作为迁移种子，不再提供这些控制项。

挂念发布 `availabilityOnly` 作息，睡眠只提供 bed/wake，忙碌只提供时段及细排中的休息。插件负责回复规则；无插件时这些作息仍供「在线状态」显示，但不阻塞聊天。主动消息的忙碌押后、起床缓冲和醒来概率仍在挂念，独立于被动回复。

停用插件后不恢复旧 APP 规则；已有本地等待释放，个人云等待须成功同步后释放，生成中的请求不撤回。新的网关/生成器支持立即释放已关闭规则的等待及手动状态跨午夜到期，需要更新 `ai-phone-push` 和 `push-generate`，无需 SQL 迁移。插件安装包为随宿主发布的 JS 文件，本挂念 ZIP 不会代替安装聊天插件。

## 0.9.20：关闭小手机后的延后回复

启用个人离线推送，并更新宿主、个人云网关 `ai-phone-push` 和生成器 `push-generate` 后，进入忙碌/睡眠等待即上传加密任务。聊天显示「等待已同步云端」后可以关闭小手机；云端检查概率和时段，到点后复用原有模型生成、通知和聊天回填。扫描约每分钟一次，积压或模型耗时会增加延迟；概率检查本身不调用模型。

连续补发、修改 API 配置/绑定或挂念同步新作息时，更新尚未被云端认领的任务；不因补发重置计时或增加抽取。已经生成中的请求不切换 API。关闭后按最后成功同步的请求与作息快照执行，未上传的消息和设置无法被云端读取。

上传前本地即暂停执行该等待；确认丢失会重试同一个任务，不另发本地请求。旧云函数通过能力探测回退本地等待并明确提示。完成/失败/取消后的任务清空加密请求；取消保留空任务记录，防止迟到的上传重新创建任务。取消必须经云端确认；个人云项目切换时不会把旧等待复制到新项目。

无需新增 SQL 或单独配置模型密钥。新任务仍使用现有个人云的加密保存方式，云端有解密能力。安装包包含前述精力修复，完整更新还需 `push-recheck`。本地回归含真实客户端、网关和 worker 的模拟请求，不等同于手机关页实测。

## 0.9.19：专注中按概率偷空回复

「云端 → 忙与睡」新增默认开启的「根据日程找空档」。需要「你发消息时也照此办」开启，且等待分钟数大于 0。

- 普通事务仍按设置的分钟数上下浮动四成后偷空回复。
- 会议、上课、考试、驾驶、训练等通过日程标题关键词识别；按等待间隔检查，每次默认 25% 概率偷空回，没有细排也适用。未抽中继续等待，进入明确休息时段可回复，忙完后兜底正常回。概率可调 0–100：0 只等休息或结束后的缓冲（最多 5 分钟），100 在首次检查时回。不会虚构正式休息，也不会补抽关机期间错过的检查。
- 连续发送合并进同一个等待，到点统一读取最新消息。不因多点发送反复计时或增加概率抽取次数；原定时间到了但定时检查还没运行时也不会新建一轮等待。
- 到点核对最新日程；活动延长、转入下一项忙碌或睡眠时重新安排，错过的休息间隙也会重新选时机。提示词区分正在偷空、休息间隙和已经忙完。关闭开关恢复原来的定时等待，0 分钟不等待，紧急词保留原有优先规则。

这是规则升级，不增加模型调用，也不保证识别任意措辞。0.9.19 的等待由宿主执行；0.9.20 可在确认同步后交给云端。已存在的等待在原定时间核对新规则。本项需要同时更新宿主和 APP；云端主动消息的押后规则保持原样。安装包包含 0.9.17 的精力修复，该部分仍需更新两个云函数。

## 0.9.17：细排预设与精力尺度

- 整天生成、单条重写、时段细排分别匹配 `daily`、`schedule-edit`、`schedule-steps`，各有独立预设。细排只接受当前时段内的动作，不重写当天安排、精力或情绪；返回整天日程时报错并保留原数据。
- 正常睡眠的起床精力建议 70–90，普通会议/工作扣 3–8，连续数小时高强度活动扣 9–15。单条总变化硬限制为 ±15，旧日程也按新上限计算；不改写已有起床精力和历史记录。轻微不适建议扣 1–3，新生成身体状况每条最多扣 8，状况总扣减上限 12。自然清醒缓降照旧，重病、熬夜等低精力情境仍可存在。
- 日程详情的「预计做完后」按结束时刻计算；旧条目没有结束时间则显示「到点后」，与原来立即记账的规则一致。
- 更新安装包后细排立即使用独立标签。新起床基线和建议尺度在下次生成时应用；无需为了旧日程的单项上限重新生成一天。云端一致计算需在宿主「设置 → 云服务部署」更新 `push-recheck` 和 `push-generate`，无需 SQL 迁移。已冻结的未来生成原料会在 APP 正常刷新上传后更新。

## TA怎么想起你

1. **生成今日生活面** — `ai.generate`（预设 `guanian-daily`）按人设生成TA今天的心情（当天的**情绪底色**）、精力基线、位置、作息（`wake` 起床 / `bed` 上床，可过零点）和 5–9 条日程。
   提示词先给模型「日历现实」（周几、周末、节假日、寒暑假、季节）、前 5 天的日程骨架和昨天的余波（几点睡、最后一次聊完的情绪），再要它定今天的底子：昨晚睡得怎样（`sleep`）、身上的小状况（`body`，最多两条，落成带半衰期的 `conds`，精力和情绪自动算进去）、情绪底色，最后排日程。每条日程的 mood 要求用可感的状态词并和 cost 对得上。
   日程不填满一天：每条有开始和结束时刻，事与事之间可以留空档。此刻的状态按四段判：**睡着**（bed 到 wake 之间，跨零点也算）、**正做着某条**、**空档**（上一条做完、下一条没到，「歇着」）、**睡前**（最后一条做完到上床之间）。所以晚上最后一件事做完后TA不会一直「在做那件事」到半夜——先是睡前，到点就睡了；睡着的时段不排心动时刻，聊天注入和云端到点生成都会写「在睡觉，被吵醒也只迷迷糊糊回一两句」，到点真发之前云端再查一次，睡着了就不发。老数据没有 wake/bed 的，用免打扰时段当睡眠窗。
   可选「自动生成」：设置里开了并定一个时刻，挂念开着（哪怕在后台）时每天到点自动生成并编排；当天错过了，下次打开时补。浏览器整天没开就生成不了。
   每条日程带一个 `cost`（-15～15，负=消耗、正=回血）和一句「做完之后的情绪」。此刻精力 = 基线 + 已发生日程的 cost 累加 + 身体状况及聊天带来的加减（负向合计最多扣 12） − 随醒着时长的缓降（22 点后陡降），每分钟重算，卡片上看得见在动。
   会先 `calendar.read` 读取TA在系统日程 app 里今天已定的安排，作为必须保留的固定项；生成结果再经 `calendar.write` 写回系统日程（条目 id 以 `guanian_` 开头，重新生成时只清理自己写入的，不动手动条目）。
2. **逐条改日程 / 细排** — 时间轴上只留时间、标题和一句细节；耗多少精力、做完之后的情绪都收在详情里。点开任一条可以看到这些，再「细排这段时间在做什么」——按这条到下一条之间的时段拆出 3–5 件具体在做的事（一次 `ai.generate`，结果存在这条日程上）。也可以「重新生成这一条」（留一句要求，比如「改成下午、别那么累」）或直接删掉。改完照旧写回系统日程；心动时刻不会自动跟着变，要跟上就按「♥ 重新编排」。
3. **念头什么时候定** — 两种模式（设置 → 起念 → 「念头什么时候定」）。
   **随用随判（默认）**：早上只生成生活面，**不排念头、不调模型**；白天云端每次醒来（cron 每 5 分钟）看一眼此刻的状态，想起来了才当场排一个近期时刻。更像真人 —— 决定念头的东西（你回没回、刚聊了什么、此刻精力）一整天都在变，留到最后一刻判才准。需要开着云端复核。另有**配速**：允许用掉的额度 = 今天已过去的比例 × 每日额度（至少放开 1 个），防止上午就把额度用光。
   **早上定完**：一次 `ai.generate`（预设 `guanian-impulse`）把今天所有心动时刻定死。浏览器不常开、没配云的话用这个。念头**不挂在日程节点上**：日程只作为背景，另外给一份「今天剩下的时间长什么样」——不按固定网格采样（会漏掉夹在两点之间的短日程），而是按日程自己的边界逐段列，每条带 `end`、那一刻的精力和 `busy`。模型据此自己说想在哪些时刻找用户。
   两种模式下每个念头都带 `time`（最想说出口的时刻）、`until`（保质期，过了就不新鲜了）、`about`（由头）、`sem`/`topic`/`intent`/`why`。模型自己挑的时刻说了不算，五道硬拦照走：时刻必须晚于现在、不落在免打扰或睡眠窗、同一时刻只留一个、相邻不小于最小间隔、超出今日额度的记成「想过但没发」。
4. **预约离线主动消息** — 对通过复核的时刻调用 `AiPhone.push.wake({ characterId, fireAt, intent })`。服务端挂载成功显示「离线可达」（浏览器关了也能收到推送）；失败降级为「仅在线」（本地轮询触发）并显示原因。
5. **此刻预览** — 预设 `guanian-preview` 基于TA当下状态生成一条TA此刻会说的话，只展示不发送、不占额度。
6. **到点再判一次** — 真要发之前，云端按「有没有等到回复 / 是不是正聊着 / 离上一条主动多近」合成一个不合时宜度，够高就不发；判据回写计划，点开那条主动消息能看到。
   通过之后，云端会按寄存的日程和「情况」重算TA**到点时**在做什么、什么情绪、剩多少精力（和面板上的算法一致，不多调模型），补进请求再生成——预约里冻着的是编排那会儿的状态，不补的话晚上发的消息还带着早上的精气神。
7. **情绪跟着聊天走** — 每次复核那一次模型调用会顺带判一条 `feel`：这段聊天下来TA什么情绪、因为什么、对精力是加还是减、多强、多久淡一半。
   它作为一条「情况」压进当天的栈里，按半衰期指数衰减；此刻情绪 = 栈里分量最重的那条（或刚做完那件事的余味），都淡掉了就露回当天的情绪底色。
8. **判决与起念分开过闸** — 复核那一次调用其实干两件事：**判决**（重判已排好、还没到点的时刻，改亮改灭）和**临时起念**（新加一个计划里没有的时刻）。判决需要还有没到点的时刻，起念不需要——日程走完的晚上才是最该起念的时候。两组各有各的准入条件，但共用同一次调用，所以频率（每日上限、最小间隔）仍然共享，不会多花钱。哪一组没过，提示词里就不带它，模型硬塞回来也会被丢掉。
   云端判断借的是一条预约里冻着的模型凭据。为了TA一个时刻都没点亮的日子云端也能动，每次编排都会另挂一条 48 小时后才到点的**哨兵预约**专门当模板，到点云端直接作废（cron 只派 36 小时内更新过的计划，够覆盖）。
9. **改约**（复核的一部分）— 复核判某个时刻不该发时，不再一律取消：如果只是这个点不合适（刚聊完太密、这话晚点说更合适、这会儿说了会打断你）而话本身还想说，模型可以在 `defer` 里给一个今天更晚的 HH:MM，整条念头连同动机挪过去，不额外占今日额度。新时刻照样过免打扰、睡眠窗、最小间隔、时刻去重这几道硬拦；**能挪多远由这个念头自己的 `until`（保质期）决定**，过了保质期这话就不新鲜了，宁可作罢——不数改约次数。本地复核和云端复核都支持。
   改约和「忙与睡」的押后是同一件事（都是把时刻往后挪），所以共用一套记账和角标（时间轴上都显示「押后 HH:MM」），只在详情的历史里分开记：押后是**到点那一刻**发现TA正忙/睡着，机械顺延、不调模型；改约是**复核时提前**按聊天语义判的。提示词里明确要求模型不要为「正忙」改约（那个到点自动会处理）。
10. **自发起念**（云端复核的一部分，设置里限次）— 没有新聊天时，TA刚做完一件有分量的日程（精力变化明显或有情绪余味）、或者你们已经 3 小时没联系，云端也会让TA按此刻的状态想一想要不要找你；不想就老实作罢。每次都是一次裁决调用，所以单独有每日上限，重新编排后清零。起成的时刻在时间轴上标「自发·」。
11. **聊天改日程**（设置里的开关，默认开）— 动态复核那一次判断顺带看聊天里有没有说定、取消、或临时被叫走的安排，有就直接改今天的日程（新增 / 挪时间 / 删掉），一次最多 2 条，只动还没到点的条目，改完写回系统日程。这类日程在详情里标着「聊天里…」的来源。
12. **注入聊天**（设置里的开关，需 `chat.context` 权限）— 打开后，TA此刻在做什么（细排过的那条日程会精确到当前那一小步）、什么情绪（连带底色和缘由）、剩多少精力、接下来要做什么，
   会作为一段状态覆盖式写进你和TA的聊天提示词，每次刷新盖掉上一次，不会堆进聊天历史。
   这段由内置预设的「▸ 自定义 APP 实时状态」条目渲染，默认排在 `prompt_order` 最末——系统提示词整段共用一个缓存断点，往前挪会让人设和世界书每轮都重新计费。
   状态只在挂念开着的时候刷新，所以注入的小标题里带了快照时刻（【挂念 · 14:32 的状态】），角色自己能看出这份状态是不是旧的。
   关掉开关会立刻写空串撤销；在小手机的应用权限页收回 `chat.context` 也是一样的效果。
13. **忙与睡**（设置里，默认关）— 云端到点真发之前看一眼TA在干嘛。正做着顾不上看手机的事（生成日程时模型给每条标 `busy`；老日程按标题猜：上课、开会、开车、考试这类），就把这条预约押到那件事结束再加几分钟，从原时刻起押得超过上限就作罢；押后的时刻面板上标「押后 HH:MM」，到点云端再判一遍（还忙就再押）。睡着了按选项办：不发 / 押到起床后 / 按概率迷迷糊糊醒来说一两句（概率由预约 id 定，同一条不会反复掷）。只管云端预约，「仅在线」的本地预约不受影响。
    「你发消息时也照此办」（默认开）把作息和今天顾不上看手机的时段通过 `chat.setReplyGate` 寄给小手机，你发消息时由小手机自己判：睡着押到起床再加几分钟才回（「概率醒来」时按同一概率被吵醒、迷迷糊糊回一两句），普通忙碌按「偷空等待／检查间隔」稍等后回；开启「根据日程找空档」后，专注事项按该间隔检查偷空概率，或等明确休息/忙完。押后期间再发合并进同一轮，不重置计时、不增加抽取次数；「救命、医院、快回」这类字眼不押。押后的那次回复提示词里会补一句「刚起床才看到」或「偷空回的」。挂念关着也管用；0.9.20 在确认同步个人云后，关闭整个小手机也会执行。未同步云端时由桌面壳到点触发，关闭后需下次打开才继续。
14. **惦记账本**（设置 → 聊天，默认开）— 复核那一次调用顺带从聊天里记下值得跨天记住的事：没聊完的话头、约好或答应了的事（带时间）、重要的日子（带日期，生日/纪念日按年循环）。话头几天没再提就淡掉，约定过点一天作废。账本寄在云端计划的 context 里，本机和云端复核都往里记、往外销，`at` 大的赢。用它的地方：起念判断（约定快到点、到日子、话头没接完都是由头）、生成明天的日程（约好在当天的必须落进 schedule）、注入聊天（TA聊天时知道自己心里还挂着什么）、到点发消息的备忘。云端自发起念多了一个由头：约定前 30–90 分钟想打个气、过点 1–3 小时想问结果、到日子当天想说一句，每个阶段只提一次。账本和时刻是联动的：复核时同一件事只进一边——今天之内说得掉的排成时刻（`extra`，`from` 记着出自账本哪条），今天说不掉的才记进账本。由账本起出来的时刻真发出去之后自动回写：话头说完就了结，约定和日子只标「提过了」（话没完，到点还得问结果）。反过来你在面板上了结或删掉一条惦记，由它起的、还没到点的时刻会一起撤掉。「心动」页的「惦记」卡：点一行展开，能看到为什么记它（模型记的由头）、类型和时间、谁记的、提起过几次；了结和删掉都收在展开里，不会一戳就没。标题旁「已了结 N」翻得到最近一周了结的，可以恢复。
15. **替TA发朋友圈**（设置 → 分寸 → 起念来源与克制，默认开，一周最多 3 条、至少隔 6 小时）— 两条路：**生活轮**——云端每小时按时段、精力、刚做完的事掷一次骰子（和「朋友圈节奏」插件同一套算法，不调模型），中了就把由头记进计划 `context.outbox`；**分享型念头**——复核（本机或云端）判定某件事更像发给所有人看而不是说给你听的，在 `post.hint` 里给一句由头。帖子只能在小手机前台入库，所以浏览器关着时只记起意和时间点，下次打开由宿主按人设成文、走朋友圈定时发帖的整条管线（人设、记忆、去重、配图、NPC 互动），按实际发布时间入库，原起意时间单独保存在挂念记录里。积压多条时只保留最新一条，其余标为合并未发布，真正发布前再次检查间隔和周额度。一周几条、隔几小时是发圈唯一的一套数：本机和云端共用，云端的起意预留与本地已发布记录分开，取得帖子编号后才计入已发数量，并写进变量池 `moments`；「朋友圈节奏」插件看到就让位，不会两个骰子各掷各的。宿主要 ≥ 带 `AiPhone.moments.post` 的版本，否则记进诊断、起意留在 outbox 等下次。
16. **诊断** — 每个候选时刻为什么发 / 为什么没发、预约结果，都记录在面板底部的诊断区。

- 判断时回看几句（6–40，默认 24）：编排、本地复核、云端裁决喂给模型的最近几句聊天，每句最多 200 字
- 聊天改日程（聊出来的安排落到今天的日程上，默认开）
- 注入聊天（把TA此刻的状态写进聊天提示词，默认开）

## 权限

`app.data.read/write`（本 app 数据）、`characters.read`、`chat.read`、`chat.context`（注入聊天提示词）、`ai.generate`、`calendar.read/write`（与系统日程互通）、`push.wake`（离线主动消息，主程序权限，随本 app 一并落地）、`moments.write`（替TA发朋友圈）、`ui.toast`。

## 数据

`db` 集合：`settings`（单条配置）、`days`（每角色每天一条生活面，含情绪底色与会衰减的情况栈 `conds`）、`plans`(每角色每天一条编排结果)、`logs`（诊断日志，保留最近 40 条）。

## 零点到生成之间

零点一过今天就换了记录，但今天还没生成时不会当TA凭空消失：睡没睡、几点醒都按昨天记录里的作息来，聊天状态、回复闸门、在线状态照常，直到今天生成为止。时间线最上面多了一行「昨晚 · 睡觉」，凌晨点亮的是它，不再是今晚那条。

## 替TA定死忙闲

在系统日程里给TA写安排时，标题末尾加「·忙」或「·闲」（例如「周会·忙」），生成时这件事顾不顾得上看手机就照你写的来，模型不再自己猜。前几天的生活面会喂 7 天给模型，要求跨几天的事按筹备、进行、收尾、余波连成线。

## 两台设备同时开着

电脑和手机都开着挂念时，一天里只有一台负责生成、编排、预约和云端；另一台自动变只读。谁先按下生成或编排，今天就归谁管（不是谁先打开）。

为什么要锁：预约 id 带本机随机后缀、登记簿也各存各的，两台各排一次就在服务端挂出两套 `push_jobs`，谁也撤不掉谁的，到点发两遍、扣两份额度；云端裁决还只能被先打开的那台取走一次，另一台从此看不到TA改过什么主意。

- 锁记在当天云端计划行的 `context.owner` 里，粒度就是那一行（角色 + 日期），**零点自然释放**——第二天谁先开谁负责，只带手机出门的日子不用管。
- 锁不在首页露脸：诊断页「云端 → 今天谁在管」写明是哪台，只读的那台在那里点「改用这台」接手——会先撤掉原来那台挂在服务端的今日预约和 48 小时哨兵，再把锁抢过来，接着接管云端生成的今天（没有就按本地重排）。在只读的那台按生成或编排，会提示去哪儿接手。
- 清了应用数据或换了浏览器就算另一台设备，同样点「改用这台」回来。
- 没接云连接不上锁：预约只在本机挂着，不存在两台互相看不见的问题。
- 用量账本按设备分行（`app-<设备 id>`），两台的本机用量不再互相覆盖，合计和日上限把两台都算进去；「用量」页的「本机」后面带 `+N` 就是另一台今天调的次数。

## 0.9.22 主动消息等待与事实核对

忙碌只顺延，不再因旧 `until` 或“最多押后”时限直接放弃。原 `busyMaxHoldMin` 数值保留，改为“等待多久概率减半”（默认 180 分钟）：忙完准备发送时用任务 ID 的稳定样本抽一次，等待越久概率越低，不因轮询次数增加机会。每次成文复用原 API 请求核对最新聊天，已提过、已解决或事实已变化时输出作罢标记，云端不写消息、不发通知。读取最新聊天失败会等 5 分钟重试。事实可见范围取决于聊天镜像同步，未同步的手机聊天无法被云端核对。

心动列表、统计与详情统一读取发送回执，不再把时间已过当成已发送；未确认的条目保留待确认。安装此包后，还需在小手机「设置 → 云服务部署」更新网关、push-generate、push-recheck；不新增 schema。旧版已终止的预约不会因此自动重发。
