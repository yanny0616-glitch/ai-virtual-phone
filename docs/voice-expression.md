# 普通聊天与语音通话的自然语音表达

入口：设置 → 语音 API → MiniMax 配置 →「自然语音表达」。界面沿用宿主 `ui-toggle-row`、`Toggle`、`Textarea` 和 `ui-link-btn`，说明与其他字段保持同一字号；恢复默认位于提示词标题右侧。每份语音配置独立保存开关和表达提示词；旧配置默认关闭，留空或恢复默认使用内置提示词。配置绑定沿用聊天的角色/应用级联解析，不改变选定模型或音色。

开启后，普通聊天仅在原本要发送的语音条中添加表达信息，不强制把文字消息改成语音。单人语音通话保持原有单段口语输出，按行内情绪标记切分合成并依次播放。视频、群聊、自定义 APP 的提示词不在本次接入范围；自定义 APP 原有 `voice.tts({ emotion })` 不受开关影响。

## 数据流

1. `lib/chat-engine.ts` 按当前角色绑定的语音配置生成 `voiceExpression` 宏内容。普通聊天在原「聊天输出格式与富媒体」条目的「语音条」小节下展开；通话在原「语音通话输出格式」条目内展开。不在消息数组末尾另加系统消息，复用本轮聊天模型请求，不增加一次润色请求。
2. 聊天模型生成 `[语音条:<tts:happy>你回来啦！(chuckle)]`；通话直接生成 `<tts:happy>你回来啦！(chuckle)`，需要改变情绪时在同一段内添加新的情绪标记，避免与原通话“单段、不换行”要求冲突。
3. `lib/rich-message-parser.ts` 分离可读内容和 `mediaData.ttsText`。`label`/`content` 不含控制标记，历史、字幕沿用可读内容；没有情绪标记的语音条也会分离已知声音标记。普通无协议文字保持原样，纯标记不产生空语音条。
4. `lib/voice-expression.ts` 去除双语译文、校验情绪及停顿，`synthesizeChatSpeech` 调用已有 TTS 服务，把情绪写入 `voice_setting.emotion`。`auto` 和非法值不传情绪，由 MiniMax 判断。仅 2.8 HD/Turbo 保留声音标签；其他 MiniMax 模型保留情绪和停顿。关闭或改用 OpenAI 时清理控制标记再朗读。
5. 通话每段合成一次并顺序播放，可能增加段间等待；挂断后不会继续播放或合成后续段落。普通聊天继续点击合成、并发去重和持久缓存；修改配置不自动重做已有音频。编辑消息文字后，若旧 `ttsText` 与可读内容不一致，放弃旧表达文本，避免读出旧内容。

`speechExpressionEnabled`、`speechExpressionPrompt` 是 `VoiceApiConfig` 的可选字段。情绪使用共同支持的 happy/sad/angry/fearful/disgusted/surprised/calm；不强制为每句话指定情绪。短暂停顿限定为 0.01–2 秒并排除开头、结尾和连续停顿，避免异常长静音。

2.8 HD/Turbo 的内置规则列出同步接口支持的全部 19 个声音标签及中文含义，按语境在合适的位置使用，根据角色情绪、说话内容与呼吸节奏选择，不机械添加。默认表达提示词同步采用该原则，不再要求“少量”或“多数句子不用”。用户自定义的表达提示词保持原样；留空或点击恢复默认可使用新默认文案。

## 预设迁移和查看器

新建预设自带 `{{voiceExpression}}`。已有预设首次读取时，只在已存在的 `chat_output_format` / `chat_voice_format` 条目中补入宏并记录 `voiceExpressionVersion: 1`，不提升会重置用户内容的出厂版本，不改原文、条目顺序或启用状态，不创建缺失条目。迁移后用户主动移除宏不会被重复加回。完全自定义标识的条目可手动插入同一个宏。

语音配置关闭或场景不适用时宏为空；条目被关闭也不会绕过它追加规则。提示词查看器显示实际展开内容。聊天组装会等待插件启动/重载完成；单聊手动预览也执行实际请求使用的 `llm.request` 变换，包含普通和原生工具两条请求路径。只有满足当前上下文条件并实际参与请求的插件规则才显示；手动预览是基于当前历史的新预览，不能代替此前一次请求的快照。

沉默输出协议允许首行 `[本轮不回复]` 后继续输出原有内心、状态和签名；后台隐藏记录保存本轮更新，不显示新爱心、不增加未读，也不把内心全文回传模型。固定协议在允许沉默的请求中移至已有前置系统条目之后、首条对话之前，保留更早的公共前缀，并标记为「沉默输出规则」，不改变插件的沉默资格判断。挂念实时状态及插件其他内容的位置保持原逻辑；条件变化仍可能改变请求前缀，不承诺所有请求均命中缓存。

普通聊天长按「重试以下」显式携带 `generationIntent: regenerate`，即使截取历史以同轮另一条 AI 气泡结尾，也不会注入“用户未输入新消息”的续写保护提示。删除范围仍是选中消息及其后续；真正的无新输入生成保留原保护机制。

## 试听与验证

语音设置里的试听在开启时使用固定开心语气示例，2.8 模型另含轻笑，不调用聊天模型。自定义表达提示词要通过新生成的普通聊天语音或新通话轮次体验；不宣称固定示例已经验证自定义提示词效果。

- `node scripts/check-voice-expression.mjs`：真实解析器、请求组装、配置范围、双语与编辑失效、模型兼容、通话挂断、聊天去重/持久化/失败重试，TTS 使用模拟响应。
- `node scripts/check-voice-expression-browser.mjs`：隔离 Chromium 加载完整 `VoiceSettings` 组件及现有项目编译样式，使用无密钥的测试配置，验证实际配置保存、重挂恢复、开关、默认提示词、统一控件样式和单个配置编辑器；320/390px 各 21 项。默认从 `/opt/float/current/.next/static/css` 读取样式，可通过 `FLOAT_UI_CSS_DIR` 指定已有产物；不运行本机 Next 构建，不等于线上用户主题或手机实机验收。
- `node scripts/check-chat-prompt-layout.mjs`：预设迁移、真实宏展开/条目位置、插件查看器普通及原生工具路径、沉默前置，以及真实长按重试处理函数与续写保护组合；`node scripts/check-chat-silence.mjs` 验证原沉默行为。
- 领域模块定向 TypeScript 检查；相关文件 lint 与修改前版本对比，无新增问题。未进行本机 Next.js 全量构建或付费语音实测。

MiniMax 能力依据：[同步语音合成 HTTP](https://platform.minimaxi.com/docs/api-reference/speech-t2a-http)。自然感仍需用实际角色、音色和对话试听评估。
