# 挂念后台预约误发与同步展示修复

> 历史记录：以下结论、版本与发布状态保留自记录当时，不代表当前源码或线上状态；归档不表示问题全部解决。见[归档导航](../README.md)。

## 证据与边界

用户 SQL 结果确认两条任务在 2026-09-06 06:13 创建、2026-09-08 06:14 生成，两条均未关联到现存计划。接近 48 小时与哨兵特征一致，但现存字段不足以证明这两条一定是哨兵。

修改前实际 push-generate fixture 复现：前一条生成仅过 5 秒、计划间隔 60 分钟时，有关联的任务等待，无关联的任务仍生成。页面回执只读取计划中的 wakeId，遗漏无关联任务。不是同一条消息重复显示，也不能据此声称模型未读取昨晚聊天。

## 已修改

1. 云端：最近 32 份计划优先匹配哨兵；显式哨兵不生成；挂念前缀预约缺少计划时停止并写任务原因。读取失败保留重试，成文期间取消/替换仍拦截。普通有效任务和其他 APP 的预约行为保留。
2. 本地：宿主新建哨兵编号带 sentinel_，本地发送入口兼容旧意图和新编号，阻止模板发聊天。挂念提取前缀时去掉 sentinel_，避免把普通起念变成模板。
3. 展示：同步卡仅在后台单一区域折叠展示所有角色；后台增加当前角色现存最近 50 条挂念云端发送记录的只读查询，已收取与无当前计划关联的消息也可查看。查询不会修改计划/聊天/领取状态，失败保留旧数据。
