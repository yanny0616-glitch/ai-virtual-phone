# 记忆系统方案：修复 → 优化 → 重构 → 缓存

2026-09-17 与用户定稿。覆盖整个记忆系统（短期 / 长期 / 核心 / 拾光 / 挂念等后台模板）。
按阶段推进：先修不改变请求的问题，再做有开关的优化，最后重构；缓存优化等记忆定型后再做。
每完成一项：在文末「进度」打勾，写 `fork-changelog.md`，提交、推送、部署。

---

## 一、目标与原则

1. **不丢关键信息**：原话永不删除；普通小事也要记，只是标低重要度。
2. **token 变少，但不靠按 token 截断旧内容**：去掉同一段过去被重复带入的部分；远的带压缩版，细节按话题 / 时间召回。
3. **总结可信**：提示词按参考项目经验重写；总结能下钻到原消息；整理失败不推进进度。
4. **越近越全**：近期原话完整保留，不为省 token 压缩近窗（WrenWen 教训：近段压太狠比长期缺失更伤体感）。
5. **拾光并入宿主**：一个原生记忆页（参考糯叽机「记忆宫殿」分区思路，不照抄）。
6. **可观察**：记忆页显示各层实际占用，token 按模型用真实用量校准，不写死某家分词比例。
7. **安全切换**：会改变发给模型的内容的改动，一律先影子运行或带开关，用户确认后再生效，可随时关回。

### 2.2 代码现状

### 2.3 已确认的问题

1. **同一段过去被带三遍**：长期总结写完后原话仍按预算全带；核心记忆由长期记忆合成，但被合成的长期记忆也仍在带。
2. **长期总结提示词不可靠**：第三人称、100–200 字概括约 40 轮；没有时间、原话、说话人规则；模板末尾误写「核心记忆总结：」。
3. **核心记忆提示词有 bug**：「要突出」和「普通日常聊天、一般情绪波动、不确定内容」写在同一个列表里，没有「不写」标题。核心只新建不合并，越积越多。
4. **挂念判断模板把全部私聊转成文本**，一半是前缀，且与判断提示词自带的最近聊天重复。
5. **token 估算写死**（`lib/token-counter.ts:12`），不分模型；预算、显示都偏低。拾光用同一公式。
6. **长期总结和拾光各跑一套**：读同一批聊天、各自调模型、各自水位线、两处前端。
7. **默认提示词改不到老用户**：设置页保存时把整份提示词写进 `ai_phone_memory_config_v1`，只改 `DEFAULT_*` 不生效。

## 三、参考项目调研结论

来源：本次会话浅克隆各仓库读源码（2026-09 版本），糯叽机读 `nuojiji-public-2026-09-15/assets` 压缩代码。

### 3.1 逐个项目

**WrenWen**（纯文档）
- 分层：只追加的对话账本、蒸馏记忆库、自传库、日 / 周 / 月「生活时间树」、一件事一卷的「线卷」。
- prompt 按变化快慢分三区：稳定 system（人格 + 时间树）→ 历史 → 当前 user 消息里的动态块（时间、召回）。
- 缓存事故：每轮变的动态块放在历史之前，命中率中位数 87% → 52%；只改位置（放进当前 user 消息）就回到 86%。
- 近窗：预算约 8k–11.5k，条数保底 80/120；「近段被压得太狠，比长期记忆缺失更破坏体感」。
- 召回改门槛制：绝对分 75，主召回 ≤4 条，antiEcho（24 小时内召回过扣分），三层去重。
- 蒸馏坑：要求「不少于 80 字」导致编造引语；改为条件式，引语逐字回源校验。
- 「越聊越像客服」真因是漏传 temperature。

**Paramecium**
- L0 原文逐字存档（≤700 字窗口 + 向量 + FTS5）；L1 摘录必须附 10–40 字逐字引用并机械校验；L2 手写画像。
- 阶梯窗口：累计超 60K token 才压缩，保留最后 8 条，**不删原文，只推进锚点**；摘要追加，≥3 段再合并重写。
- 每轮只注入记忆目录（约 150 token），细节由模型调 recall 工具翻原文。
- 定时空请求「保温」字节对不上，白做。

**ai-memory-gateway**
- 摘要区只在尾部追加；A 区 15 轮原文、B 区当前周期，攒满轮转。
- 摘要提示词：第一人称；优先情感节点、关系里程碑、约定和决定、进行中的话题；关键原话加引号标说话人。
- 摘要区超 8000 字折叠最旧几段，代码校验折叠结果更短，不通过回滚；**生成失败不推进窗口**。
- 不要用推理模型做摘要（思考耗尽输出导致空摘要）。召回 6 小时内不重复注入。

**kiwi-mem**
- 日历层级注入：最近 3 天完整日摘要，4–7 天短版（有周总结则不带），更早按周 / 月 / 季去重。
- 日摘要保留因果与情绪质地；周总结按板块写。
- 热度 = 初始温度 × 半衰期衰减 + 召回加成；高热度全文、中热度截短、低热度不注入。
- 时间精确到分钟放静态区会让 DeepSeek 前缀缓存整段失效。

**Memory Constellations**
- 「航海日志」摘要提示词（最具体的一份）：`HH:MM～HH:MM · 主题，具体内容`，按话题或情绪转折分块；保留原话具体用词；禁用「讨论了 / 交流了 / 分享了 / 表达了」；只写发生了什么不写意味着什么；AI 的猜测玩笑不当用户状态；被纠正的只记纠正后事实；只用绝对时间。
- 召回给每条打「引用许可」：新近双命中可引用，较旧需谨慎措辞，很旧仅联想。

**Aelios**（v3-slim）
- 删掉每轮压缩模型，只留 reranker；日常最多召回 1 条、回答旧事最多 2 条，每条 ≤400 字原文窗口；低分不凑数，已在可见历史里的不召回。
- 召回追加在对话末尾，不动前缀。夜间提取的事实进审核队列，不直接落库。

**omemo**：full 全塞 system / rag 每轮额外调模型挑记忆（结果抖动，不建议学）；时间放最后一条 user 消息末尾保缓存。

**次要**
- kimi-core：滚动 history 本身会破缓存，history 锚定起点只追加；读 cached_tokens 字段路径错会显示 0% 命中。
- KI-CO：「嗯」「哈哈」这类短句不触发召回；记忆块不带分数调试信息；整理走单独便宜模型。
- imprint-memory：摘要会丢专有名词，摘要查不到时回退原始日志。
- SillyTavern Summarize 每次重写摘要破坏其后前缀；qvink 逐条短摘要替代旧消息。MemGPT / Letta：core 常驻可编辑，recall / archival 靠工具检索。

### 3.2 糯叽机

- **原文窗口按条数**：`memoryDepth` 默认 20，取最新总结 `lastMessageIndex` 之后再截 N 条；开关「上下文深度必读（无视已总结）」默认开。时间戳降频：换日插日期行，间隔 ≥2 小时插分隔，≥10 分钟才标发送时间。
- **总结触发**：按未总结条数；<6 条不做；一次 ≤500 条分段；失败 3 分钟重试；游标可手动校正。
- **总结提示词**：字数按条数分档（≤10 条 80–120 字 … 更多 200–280）；昵称、口头禅、拟声词原样保留并注明谁说的；时间必须保真（「周五下午3点打给你」不能写成「约好了联系」，明天后天换算成日期）；只总结本批新消息、不总结总结；结构化尾标签：关键词、importance 1–5（日常 1–3 不许虚高）、悬念、立场、事实 ≤3、事实失效 ≤3；可选按事件拆分（同一次调用切 1–5 块，范围铺满整批）；temperature 0.3 走副 API。
- **大总结**：小总结攒 N 条合成，子条目标 `mergedIntoBigSummary` 后不再注入但保留、可下钻。
- **永久事实**：来自总结的「事实」行；timeless 60 / episodic 12 条上限；过期事实加注别再当待发生；相似事实先规则分组再让模型判断合并（「一次性事件不与一般倾向合并」）；失效标 superseded 不删。
- **RECAP 召回**：固定带最近 3 条总结，用户说「还记得 / 上次」扩到 10 条；★5 事件与关键词命中加权；importance 随时间衰减。
- **向量召回闸门**：cos ≥0.4 或 BM25 ≥2；相对下限 40%；刚浮现过的 ×0.55 降权；cos >0.9 去重；排除已在上下文里的；topK 6；**输出按时间 / id 固定顺序，不按分数**。
- **做梦 / 固化**：游标读新材料，产出工作记忆、立场、卡片、insights、superseded。
- **缓存**：易变块用 LIVE 标记抽出拼进最后一条 user 消息；但历史原文、召回仍在 system 里，并非完全缓存友好。
- **Token 面板**：按块分类统计（人设、世界书、永久记忆、RECAP、历史、桥等），可展开看原文、标「未注入」、显示召回明细与落选候选；估算规则写死，没有实际计费与缓存字段。
- **记忆宫殿界面**：原始片段（可搜可翻可改）、分层总结（大总结展开子摘要）、事实（可信度、过时提示、沉淀 / 丢弃）、「TA 还挂念着 N 件事」、AI 整理（去重合并剔除过期）、导入导出。

### 3.3 对 float 的取舍

| 采纳 | 来源 | 用在 |
|---|---|---|
| 航海日志式规则 + 时间保真 + 原话标说话人 + 只总结新消息 + 字数随批量 | Memory Constellations、糯叽机、ai-memory-gateway | 阶段一提示词 |
| importance 1–5 不虚高、事实 / 事实失效 | 糯叽机 | 阶段三整理输出 |
| 失败不推进、严格校验、用户编辑优先 | ai-memory-gateway、拾光现有实现 | 全部整理流程 |
| 原文不删，只推进游标；窗口只在整理时跳 | Paramecium、糯叽机 | 阶段二 / 三注入 |
| 日历层级：近 3 天完整、4–7 天日总结、更早周 / 月 | kiwi-mem、WrenWen 时间树 | 阶段三分层 |
| 大总结合并、子条目保留可下钻 | 糯叽机 | 阶段三周 / 月合并 |
| 召回门槛、相对下限、去重、防回声、输出顺序固定、短句不召回 | 糯叽机、WrenWen、Aelios、KI-CO | 阶段三召回 |
| 引语回源校验 | Paramecium、WrenWen | 阶段三自动核对 |
| 按块 token 面板 + **真实用量校准**（糯叽机缺的） | 糯叽机 | 阶段一占用提示 |
| 易变块放最后一条 user 消息、断点位置 | WrenWen、糯叽机、kiwi-mem | 阶段四缓存 |

| 不采纳 | 原因 |
|---|---|
| 每轮额外调模型挑记忆（omemo rag） | 多一次调用且结果抖动 |
| 摘要设硬性字数下限 | 会编造内容（WrenWen） |
| 近窗按条数压到很小（糯叽机默认 20 条） | 用户明确要近期完整；改用「总结之后 + 近 N 天」 |
| 只给目录让模型调工具翻（Paramecium） | 依赖模型工具调用稳定性，先不做，后期可选 |

## 四、阶段一：修复（不改变发给模型的聊天内容）

预计执行约 2.5 小时。

### 1.1 重写长期 / 核心默认提示词

长期总结要点：
- 只用绝对日期时间；不写「昨天」「刚才」。
- 保留关键原话（加引号）、称呼 / 昵称，写明谁说的、谁做的。
- 承诺、约定、计划单独写，保留具体时间与条件，注明是否已兑现；与之前矛盾的写明「改为」。
- **普通闲聊、小情绪、随口提到的偏好也要记**，写短一点。
- 禁用「讨论了 / 交流了 / 分享了 / 表达了」；只写发生了什么；AI 的玩笑猜测不当用户状态；被纠正的只记纠正后事实。
- 只写本批新内容；字数随本批消息量浮动，不设下限，信息少就短。

核心记忆要点（以 `docs/shiguang-core-memory-prompt.txt` 为底）：
- 分「保留」与「略去」两段写清；关系身份与变化、重要转折、关键人物与日期、仍有效的承诺、明确的边界与相处需求。
- 区分已发生事实、未兑现约定、个人表达；同一事项以最新为准。

### 1.2 旧默认迁移

`loadMemoryConfig` 读到的 `summarizationPrompt` / `coreMemoryPrompt` 与旧默认全文一致时换成新默认；用户改过的不动，设置页提示「有新版默认提示词」。

### 1.3 token 按模型校准

- `pushApiLog` 记用量时已知请求消息与返回 `prompt_tokens`：按模型累计「中文字数 / 其他字符 → token」的滑动比例，存 kv。
- `estimateTokens(text, model?)`：有样本用样本，没有用默认比例并标「估算」。
- 预算判断、记忆页显示、拾光预算都改走它。

### 1.4 记忆页占用提示

- 聊天请求装配时（`buildChatPromptMessages`）按层记下本次注入：短期原话 / 短期事件 / 长期 / 核心 / 拾光，每角色存最近一次。
- 角色记忆详情顶部一行：「上次请求记忆占用：短期 … · 长期 … · 核心 … · 拾光 … token（模型，已校准 / 估算）」，点开看条数与预算。

## 五、阶段二：近期优化（改变请求，全部带开关，默认关，用户确认后开）

前提：阶段一新提示词跑出的总结经用户检查可信。预计执行约 3 小时。

### 2.1 原文只带总结之后 + 近 N 天

- 短期原话 = 长期总结水位线之后的全部 + 最近 N 天（默认 3，可调）。不按 token 从旧往新裁。
- 窗口只在总结完成时整体前移，两次总结之间前缀不变。
- 总结失败或落后时自动退回旧装配，不会少带。

### 2.2 核心记忆不重复带

- 已被核心记忆合成过的长期记忆不再注入（仍保留、可查、可召回）。
- 核心记忆改为「旧核心 + 新增长期 → 一份完整新核心」替换旧版，保留历史版本。

### 2.3 挂念判断模板瘦身

- 判断模板不再带全部私聊文本：只带总结之后的原话，格式改紧凑（日期作标题只写一次、时间变化才写、同一人连发合并）。
- 长期 / 核心记忆照常带，判断提示词自带的最近聊天保留。

验收：同一对话开关前后各发一次，对比请求 token 与用户核对清单（约定、称呼、近期小事）都在。

## 六、阶段三：后期重构（未开始）

预计执行约 14 小时，分 4 步，前 3 步不改变请求。

### 3.1 目标分层

| 层 | 内容 | 来源 |
|---|---|---|
| 时间线（原话） | 所有原始消息与事件，不删；按日期翻、可搜、可钉住 | 现有时间线 |
| 故事 · 日 | 每批整理产出，按天归档：发生的所有事（含小事），importance 1–5，带 sourceIds | 替代长期记忆 |
| 故事 · 周 / 月 | 满一周 / 一月合并，小事压成一两句，子条目可展开 | 新增 |
| 事实与约定 | 称呼、偏好、习惯、边界、关系、承诺；状态 有效 / 待兑现 / 已完成 / 已变化；新事实 supersede 旧事实；可钉住 | 拾光卡片迁入 |
| 核心 | 最稳定的关系事实，定期由事实 + 月总结 + 旧核心重新生成，留历史版本 | 核心记忆改造 |

### 3.2 注入（开关打开后）

| 时间 | 每轮必带 | 按话题 / 时间召回 |
|---|---|---|
| 最后一次整理之后 + 最近 3 天 | 原话 | — |
| 4–7 天前 | 日总结 | 当天原话 |
| 1–4 周前 | 周总结 | 日总结、原话 |
| 更早 | 月总结 | 周 / 日总结、原话 |
| 任意 | 核心 + 钉住 / 待兑现的事实与约定 | 其余事实 |

- 召回沿用 `lib/memory-recall.ts` 闸门，加：时间问句识别（「上周」「那天」「之前说过」→ 取该时段总结）、已在上下文的不召回、短句不召回、输出顺序固定。
- 挂念等后台模板也用同一套分层结果。

### 3.3 整理流程

- 每批（按字数切、不拆问答）调一次辅助 API，输出 `{ day: [...], facts: [...] }`。
- 自动核对：承诺、日期、称呼、新事实是否覆盖；引语回源校验，对不上的丢弃；仍缺则本批不算完成。
- 失败不推进水位；用户编辑与删除墓碑优先（沿用拾光 `baseUpdatedAt`）。

### 3.4 原生记忆页

替换 `components/memory/memory-bank-page.tsx` 详情页现有五个标签：

| 分区 | 内容 |
|---|---|
| 概览 | 占用、整理进度、待兑现约定数、待核对提醒 |
| 时间线 | 原话按日期分组，可搜、可钉住 |
| 故事 | 月 → 周 → 日折叠，重要度星标，展开到原消息，可编辑 |
| 事实与约定 | 分类筛选、状态标签、已变化旧事实折叠、可编辑钉住删除 |
| 核心 | 当前版本 + 历史版本 |
| 设置 | 影子 / 生效开关、近期原话天数、各层预算、整理间隔、提示词 |

### 3.5 拾光并入

- 拾光 APP 库（`mem_<角色>`、`progress`）与宿主旧 `type: "shiguang"` 记录迁入宿主新类型 `fact`，保留 id、sourceIds、状态、recallMode、userEdited、墓碑。
- 只读源、写新类型，不删 APP 库，可重跑；完成后 APP 停止自动整理与当轮召回，只留跳转入口。
- 旧长期记忆保留为 `legacy` 故事条目；旧核心作为核心历史版本。

### 3.6 步骤
