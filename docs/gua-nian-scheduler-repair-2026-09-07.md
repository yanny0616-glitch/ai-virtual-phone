# 挂念调度四项修复（2026-09-07）

状态：本地修复与专项验证完成，挂念 0.9.25、个人云 schema 12。未提交、推送或部署；未在用户个人云和真实手机上联调。本文补充原云端审计，不代表审计中的所有问题均已解决。

## 修复内容

1. **角色自己的普通回复不再触发一轮普通聊天起念。** 判断材料仍包含云端已经生成、手机尚未收取的消息。新用户消息可以进入普通聊天判断；角色发言中的约定线索只进入账本核对，该轮禁止新增普通起念、朋友圈和额外日程。已有普通降速规则仍执行，明确约定保留独立任务。
2. **异常有退避、停止与显式恢复。** 复核失败按 5、10、20、40、80 分钟退避，连续第 6 次失败暂停；生成或投递失败按 1、2、4、8、16 分钟退避，第 6 次暂停。正常忙碌、间隔和租约占用等待不计错。缺少生成租约 RPC 时明确停止；旧 schema 无法保存新重试字段时把计划停放在自动扫描范围外，升级并成功同步后恢复。同步卡可重试当前角色当天计划关联的任务，已保存的成文保留，不重新调用模型。
3. **被动回复不占主动消息间隔。** 间隔只取普通主动任务的实际云端生成时间，排除被动回复、接续回复和明确约定。需要等待时直接排到间隔结束，不再一分钟接一分钟地推迟。
4. **旧计划不能覆盖新计划，约定不占普通配额。** schema 12 新增 `state_version`；手机上传和 worker 保存以已读版本为条件，冲突不写回。诊断追加原子执行，裁决 ACK 不使手机已读版本失效。普通预约撤销在计划成功提交的同一事务内完成；模型在途失去写入权时撤销未提交的新预约。手机能合并已经 ACK 的普通改期、删除；普通配额、间隔和界面统计排除约定。

安装 ZIP 不会替代宿主发布或个人云升级。云端生成、系统通知、手机落盘和用户已读仍是不同时间；本次不会使系统保证关页时实时展示，也不重写旧消息时间。

## 仍有边界

本轮未处理多页面同时消费、此前暂缓的设备接管锁并发覆盖。无法匹配来源的旧普通预约不会被盲目删除。显式重试只覆盖当前角色当天计划关联的失败任务，不重放微信/快捷动作等执行结果未知的外部操作；数据库完全不可写时也无法保证持久化错误计数或尚未保存的成文。
