# 挂念模板恢复与设置反馈

## 范围与证据

用户数据确认：2026-09-09 一个角色自发尝试 3/3 已用完，另一角色 0/3，因缺少聊天模板暂停。尚无法仅凭错误信息判定用户这次具体是挂载失败、记录被撤销、读取失败还是解密失败。

当前代码存在先撤旧哨兵后创建新模板的断档窗口，且后台模板复用普通消息的订阅/免打扰检查；旧错误处理把读取失败和解密失败也报为缺少聊天模板。本轮修复这些已确认路径，不把冷战等同于故障，不修改用户次数设置。

## 行为变化

- 新模板服务端确认成功后才更新本地引用，失败保留旧引用并中断编排。普通预约清理保护当前/近期历史模板，避免其他日期仍引用的模板被撤。
- 新后台模板只保存到云端，不替换本地同会话普通预约；模板保存跳过通知订阅与免打扰门禁，真实消息保留门禁。个人云未配置的本地模式不强制建立模板。
- 后台重试读取并合并现存计划，重建模板、上传新引用、成功后恢复调度。任一前置步骤失败不请求恢复，不靠重置今日配额解决。
- push-recheck 分开报告模板未关联、记录缺失、HTTP 读取失败、解密失败；空自发判断也写入“本轮没有新增念头”。
- 设置生效说明只存在于设置面板，关闭面板后主页不显示，重新打开设置可查看。
