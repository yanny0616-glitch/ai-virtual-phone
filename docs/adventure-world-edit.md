# 冒险世界设定 AI 编辑

入口：进入已有世界 → 工具栏「状态」→「世界设定」。采用与自定义状态一致的 11px 正文、10px 辅助文字和折叠布局。

## 使用

1. 可展开「查看当前背景与 NPC」检查 AI 最初生成的资料。
2. 输入修改要求，例如「皇帝尚无子嗣；陆敬堂改成四十岁，保留姓名和立场，其余背景不变」。
3. 点击「生成修改预览」，检查每项的修改前、修改后和原因；可以放弃，或修改要求后重新生成。
4. 点击「确认保存改动」。只有保存成功才修改世界；后续剧情读取新资料，不需要重建世界。

生成预览调用一次当前冒险绑定的模型，支持取消，120 秒超时；关闭编辑器或离开面板会取消未完成生成。剧情正在生成时不能编辑，编辑生成/保存期间也阻止新剧情请求。连接错误、截断、无效格式和保存失败不会覆盖原设定。

## 边界

第一版支持世界背景、已有 NPC 姓名和人设。不支持新增/删除 NPC、改地图节点、任务、秘密档案或自定义状态。若涉及这些部分，需要另行实现对应编辑范围。

这是对世界资料的修订，不是剧情里发生的一件事；不会凭空改变玩家位分或重置任务。历史消息保持原样，NPC 旧名通过关联指向新名。任务文字和密档也保持原样，提示词明确以最新公开设定为准；如果要求与未修改的情节存在深层矛盾，程序无法保证模型完全自行协调。

修改属于世界资料，同一世界的不同存档都读取它；回到旧游戏存档不会撤销世界编辑。已有自定义状态的数值、位分和变更记录仍随游戏存档保存。

## 数据和一致性

- `lib/adventure-world-edit.ts` 是纯领域模块。预览由实际世界资料计算原值和版本，不采用 AI 声称的原值。仅允许背景 `lore`、NPC `name/personality` 三类字段，限制内容长度，拒绝重复字段和无效目标。
- `WorldSettingPlan` 只在界面内存保存，包含当前世界编号、完整骨架与修订元数据的版本指纹、逐项差异。地图坐标和游戏进度不属于编辑范围。
- `applyWorldSettingEdit()` 深拷贝世界，按稳定 NPC 编号找到唯一的地区/节点对应，同步扁平 NPC 表和 `richRegions`，保留角色编号、位置、任务关联和原秘密。无法唯一匹配节点时拒绝整批改动。
- `MapWorld.settingOverrides` 保存修订版号、是否改过背景、改过的 NPC 编号与旧名关联。新姓名不能占用其他人物的现名或旧名；同一人物多次改名继续保留早期关联。
- `saveWorldSettingPlan()` 在 IndexedDB 写事务内重读世界、检查预览版本、重新校验修改，再写入整个世界；成功后才更新本机内存缓存与 `MapApp.activeWorld`。没有调用游戏存档写接口。
- `generateWorldSettingEdit()` 只发送公开世界背景、NPC 编号/姓名/人设/地点和用户要求，不发送 DM 密档；输入上限 100000 字符，要求上限 4000 字，严格 JSON 解析，截断回复不产生预览。
- `refreshDMWorldSettings()` 在场景、裁决（含自由交流后的直接裁决）和结局请求前，用世界 ID 重新读取已保存资料，替换缓存事件上下文中的旧背景与 NPC。修改过的公开资料也进入角色请求、提示词预览和冒险总结；DM 已携带完整当前背景与节点人设时，只补充修订优先级和旧名关联，不重复整份人设。

## 验证

- `node scripts/check-adventure-world-edit.mjs`：纯规则、预览不写入、节点同步、重名/定位冲突、旧名关联、无关资料保留、取消/错误/截断、保存失败注入与过期拒绝、实际 DM 请求读取新资料。数据库适配器与模型回复均为隔离测试数据。
- `node scripts/check-adventure-status.mjs`：原有自定义状态请求链路，加上真实角色发言和提示词预览读取新世界资料的兼容性。
- `node scripts/check-adventure-world-edit-browser.mjs`：真实 React 组件，Chromium 320/390px 各 31 项检查，涵盖生成、预览、放弃、保存失败/重试、取消/关闭后的迟到回复、过期预览、字号和溢出。截图保存至 `out/adventure-world-edit-browser/`。

本地没有调用真实模型、读取用户手机存档或运行 Next.js 全量构建；实际发布走 GitHub Actions。
